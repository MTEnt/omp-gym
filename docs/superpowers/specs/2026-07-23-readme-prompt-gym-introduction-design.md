# README Prompt Gym Introduction Design

**Date:** 2026-07-23  
**Status:** Approved

## Goal

Make the repository landing page immediately explain what a prompt gym is, why it is useful, and how `omp-gym` works with OMP without overstating the current implementation.

## Audience

OMP users deciding whether the project is relevant, followed by contributors who need a concise model of the intended optimization loop.

## Opening structure

Replace the current two-line description with four concise sections before `Current status`:

1. **Definition:** Describe a prompt gym as an evidence-driven feedback loop that improves reusable AI instructions from representative tasks generated by real work rather than from intuition alone.
2. **Benefits:** Name project-specific learning, repeatable evaluation, held-out validation against overfitting, and review-first safety.
3. **OMP integration:** Show the intended sequence: harvest project-scoped OMP sessions, mine representative tasks, review tasks, replay the current and candidate skills through OMP, compare held-out results, and stage a reviewable `SKILL.md` proposal.
4. **Implementation boundary:** State that the full automated loop is the product direction while the current release does not yet orchestrate every step end to end.

Retain the existing `Current status` table as the authoritative capability inventory.

## Accuracy rules

- Distinguish the intended loop from capabilities available through the current CLI.
- Do not claim autonomous production changes or automatic adoption.
- Explain that candidate changes are staged for human review.
- Keep OMP and SkillOpt links.
- Use plain language before implementation terminology.

## Scope

Only `README.md` and this design record change. No CLI behavior, code, status-table entries, installation steps, or release version changes.

## Verification

- Read the rendered opening top to bottom and confirm it answers: what is it, why use it, how does OMP participate, and what works today?
- Confirm the existing status table remains intact and does not contradict the new introduction.
- Run the repository documentation-adjacent CI contract before pushing to `main`.
